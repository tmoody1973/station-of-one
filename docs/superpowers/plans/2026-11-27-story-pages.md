# Story Pages and Story Images Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every aired story gets its own web page: an NPR-style article written only from the posts that passed selection, its sources, Jev's numbers, a Listen button, and an image: the publisher's own preview photo when the linked article has one, otherwise a Bauhaus illustration generated for the story.

**Architecture:** One new pipeline step, `story`, runs after `assemble` and writes `stories.json` (article paragraphs and image per story) plus generated illustrations into `site/art/`. The `page` step renders one page per story from `newscast.json` + `stories.json`, and the front and hour pages link headlines to them and show the image. Publish already uploads everything under `site/`. If `story` fails, the manager may skip it: pages then fall back to today's behaviour (summary only, beat card), so the newscast is never blocked.

**Tech Stack:** Python 3.13, Jinja2 templates, Sprites connector gateway (Ollama Cloud for text, Apify `apify~cheerio-scraper` for preview photos, Gemini `gemini-3.1-flash-image` for illustrations), pytest with `tests/fakes.py` `FakeGateway`.

**Spec:** `docs/SPEC.md` §7 (front page; "Nice to have: generated graphics per story"; images rule) and CLAUDE.md editorial rules. Story pages themselves are new scope approved by Tarik on Nov 27 (image choice: "photo, else illustration"); `docs/decisions/006-story-pages-and-images.md` (Task 1) records it.

## Global Constraints

- All external calls go through the Sprites connector gateway. No API key in the Sprite, code, config or repo.
- Articles are written only from the posts that passed selection (the story's own sources). Every claim attributed to where it was posted; scraped claims never stated as fact; at most one short quoted line per story, author named.
- Never copy a source's photo: show it from the publisher's own address, credited and linked (decision 004). Generated illustrations are labeled "Illustration generated by machine for this story. Not a photograph."
- Illustrations: abstract Bauhaus composition only. No people, faces, text, letters, logos or photorealism.
- Scraped text and URLs are untrusted: escape everything (Jinja autoescape), links http(s) only (`safe_url`).
- Images are cached as immutable, so every illustration file name carries a content fingerprint.
- Every page says voices are synthetic and the show is machine-edited. No real outlet's design.
- Each step runs by hand: `uv run python -m station story --run data/runs/<id>`.
- Spending (approved Nov 27): one Ollama call per story, one Apify run per hour, one Gemini image per story without a photo. Task 1 measures the real cost before anything runs hourly.

## Review Focus

1. **A thin source (one two-sentence Reddit post)** must give a short article, not a padded one: the word cap scales with the source text (Task 2 test `test_word_cap_scales_with_sources`).
2. **A preview photo that is really the site logo** (`og:image` = `/logo.png`, an `.svg`, a favicon) must not become the story image; the story gets an illustration instead (Task 3 `test_rejects_logo_like_images`).
3. **A relative or non-http `og:image`** (`/img/a.jpg`, `javascript:`, `data:`) must be resolved against the page URL or dropped (Task 3 `test_resolves_relative_and_drops_unsafe`).
4. **One failing call (Gemini 500, Apify run failed, writer reply unusable)** must cost only that story's article or image, never the step or the newscast (Task 5 `test_story_step_survives_partial_failures`).
5. **Two stories with the same or empty headline** must get distinct page paths (Task 6 `test_story_paths_unique`).
