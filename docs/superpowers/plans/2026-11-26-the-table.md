# The Table Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A daily six-minute debate show, The Table (on air as WNCL): two agents argue the pettiest dispute in yesterday's feeds, Jev scores every claim, and code (never the writer) declares the winner.

**Architecture:** Same shape as the newscast: one module and one CLI command per step, each reading and writing files in a run folder `data/table/<YYYY-MM-DD>/`. Steps: `threads → topic → argue → referee → script → voice → assemble → page`, then the existing `publish`/`archive`. Reuses the gateway, Jev, the Ollama writer, Gemini two-speaker TTS, ffmpeg assembly, the page templates and the hot-topic screen (`station/steps/topics.py`). Runs once a day after the 7 am newscast's `finish`, from yesterday's posts.

**Tech Stack:** Python 3.13, SQLite, Jinja2, ffmpeg; TypeSafe Jev (`jev-latest`), Ollama Cloud (`deepseek-v4.1-flash`), Gemini `gemini-3.8-flash-tts` — all through the Sprites connector gateway.

**Spec:** `docs/SPEC.md` §11 (format table and rules), `docs/Station of One PRD.md` "The Table" (T1–T10), `docs/STATION-ID.md` (WNCL, line 3).

## Global Constraints

- Format: question 0:30, opening claims 1:30, three rounds 3:00 (one claim each per round, Jev's ruling read after every claim), verdict 0:30, season record 0:30. About six minutes.
- Cast: the Anchor (careful, cites sources) and the Uncle (confident, full of theories, often wrong; "a character defined by his theories, not by any background or group"). Jev never speaks; the Anchor reads its rulings.
- Topic: Jev scores yesterday's threads on "real two-sided dispute?" and "low-stakes?"; the top thread passing both is the question. Elections, contested policy, religion and health are excluded in code (hot-topic screen, `HOT_TOPIC_MAX = 0.5`).
- Agents argue positions found in the feeds, attributed as "some posters say." Never voice or impersonate a real person. **No usernames or handles in Table scripts** (commenters are private individuals).
- Each claim goes to Jev with both sides' sources. Scores are fixed before the verdict is scripted, so the writing model cannot pick the winner. Ruling lines are inserted by code, word for word: "That claim: 14% likely true."
- Station ID on air: "WNCL, broadcasting to a potential audience of one." The page and feed say voices are synthetic and the show is machine-edited.
- Own page, own card on the front page, own items in the podcast feed (episodes stay in the feed), running season record stored on the Sprite.
- Log every Jev answer with its probability (`decisions` table). Keep a run log per Table build.
- It replaces nothing in the newscast; a Table failure never touches an hourly build. "If not working by Sunday noon, ship without it."

## Review Focus

1. **A day with no qualifying thread** (all hot topics, or no real dispute): no episode, a run-log note, and the front-page card keeps the last episode. Test in Task 2.
2. **The writer names a real commenter or quotes a handle**: the draft is rejected and retried; a second failure stops the episode. Test in Task 3.
3. **The writer tries to influence the verdict** (claims "the Uncle wins", or edits the ruling numbers): rulings and verdict are code-inserted; any script line containing a percentage or a winner phrase is rejected. Test in Task 5.
4. **A tie in Jev's totals**: verdict "a draw", record counts it as a draw. Test in Task 4.
5. **Jev or Gemini fails mid-episode**: the step fails, the station manager may retry once, and no half episode is published. Test in Task 6.

### Task 2: Topic pick (Jev)

**Files:** Create `station/table/topic.py`, `tests/table/test_topic.py`

**Interfaces:**
- Consumes: `Thread`; `hot_topic_question(i)` and `HOT_TOPIC_MAX` from `station/steps/topics.py`.
- Produces: `TOPIC_QUESTIONS` per thread `i`: `dispute_{i}` (noul: "Do the comments in `threads[i]` show a real disagreement with two sides?"), `low_stakes_{i}` (noul: "Is `threads[i]` low-stakes — tools, habits, taste or a sports-bar argument — rather than something that affects people's safety, money or rights?"), `hot_topic_{i}`; `score_threads(gw, threads: list[Thread], limit: int = 25) -> tuple[list[dict], str]` (one Jev request; state carries each thread's title plus up to 12 comment texts at 600 chars; returns per-thread `{story_id, dispute, low_stakes, hot_topic}` and the model); `pick_topic(scored, dispute_min=0.6, low_stakes_min=0.6) -> dict | None` (excludes `hot_topic >= HOT_TOPIC_MAX`; highest `dispute × low_stakes`).
- CLI `python -m station table-topic --run data/table/<day>` writes `topic.json` (`{"thread": ..., "scores": ..., "question": null}` or `{"none": true, "reason": ...}`); every answer goes to `decisions` with `question_id` `table_dispute` / `table_low_stakes` / `hot_topic`.

### Task 3: Argue (writer drafts claims, no verdict)

**Files:** Create `station/table/argue.py`, `tests/table/test_argue.py`

**Interfaces:**
- Consumes: `topic.json`, the thread's comments, Ollama `POST /api/chat` (`deepseek-v4.1-flash`, `think: false`, temperature 0.6).
- Produces: `Claim(side: "anchor"|"uncle", part: "opening"|"round1"|"round2"|"round3", text: str, source_ids: tuple[str, ...])`; `draft(gw, thread, question) -> tuple[str, list[Claim]]` returning the one-line question ("Is X better than Y?") and 8 claims (2 openings, 3 rounds × 2). JSON-only reply, parsed and validated: every `source_ids` entry is a comment id from this thread; the Anchor's claims cite at least one source; no `@handle`, no comment author name, no "I am <real person>"; each claim ≤ 60 words; claims attribute ("some posters say…", "one commenter argues…"). On a failed check, one retry with the problems listed; a second failure raises (Review Focus 2). The prompt carries the cast descriptions verbatim from Global Constraints and says the writer must not say who wins.
- CLI `table-argue` writes `claims.json`.

- [ ] **Step 1: Failing tests:** `test_parses_eight_claims`, `test_unknown_source_id_rejected`, `test_author_name_rejected_then_retry_succeeds`, `test_second_failure_raises`.
- [ ] **Step 2–4:** FAIL, implement, PASS. **Step 5: Real draft** for the picked thread; read it; record one sample claim per side. Commit.

### Task 4: Referee (Jev scores every round claim) and the season record

**Files:** Create `station/table/referee.py`, `tests/table/test_referee.py`; modify `station/store.py` (table `table_episodes`)

**Interfaces:**
- Produces: per round claim `k`: `true_{k}` (noul: "How likely is `claims[k]` to be true, given `sources`?") and `answered_{k}` (noul: "Does `claims[k]` answer the other side's previous claim?"); `referee(gw, claims, thread) -> tuple[list[Ruling], str]` with `Ruling(claim_index, p_true, answered)`; one Jev request with both sides' cited comment texts in state; `points(r) = r.p_true + (0.25 if r.answered >= 0.5 else 0)`; `verdict(rulings, claims) -> {"anchor": float, "uncle": float, "winner": "anchor"|"uncle"|"draw"}` (draw when totals differ by < 0.05; Review Focus 4). Openings are not scored.
- Store: `CREATE TABLE table_episodes (day TEXT PRIMARY KEY, question TEXT, anchor REAL, uncle REAL, winner TEXT, story_id TEXT)`; `record_episode(db, ...)`, `season_record(db) -> {"anchor": wins, "uncle": wins, "draw": n}`. Every answer logged to `decisions` as `table_true` / `table_answered`.
- CLI `table-referee` writes `rulings.json` (rulings + verdict + record) — written **before** any script exists.

- [ ] **Step 1: Failing tests:** `test_one_request_two_questions_per_round_claim`, `test_points_and_winner`, `test_draw_within_005`, `test_record_counts_wins_and_draws`.
- [ ] **Step 2–4:** FAIL, implement, PASS. **Step 5: Real run**; record the six rulings. Commit.

### Task 5: Script with fixed rulings

**Files:** Create `station/table/script.py`, `tests/table/test_table_script.py`

**Interfaces:**
- Consumes: `claims.json`, `rulings.json`, Ollama.
- Produces: `parts(question, claims, rulings, verdict, record) -> list[TablePart]` with `TablePart(index, kind: "question"|"opening"|"round1"|"round2"|"round3"|"verdict"|"record", title, turns: tuple[Turn, ...])` (reuse `Turn(speaker, text)` from `station/steps/write.py`; speakers `Anchor`, `Uncle`). The writer only phrases the question intro and each speaker's delivery of their own claim (in character, keeping the claim's meaning and attribution). Code appends after every round claim the Anchor line `f"Jev's ruling. That claim: {round(p*100)}% likely true."`, and writes the verdict and record parts entirely from templates: verdict = totals and winner (or "a draw"); record = season standings, then "WNCL, broadcasting to a potential audience of one." Writer output containing a percentage, "wins", "winner", "the verdict" or a changed ruling is rejected (Review Focus 3).
- CLI `table-script` writes `script.json`.

- [ ] **Step 1: Failing tests:** `test_rulings_inserted_verbatim_after_each_round_claim`, `test_verdict_and_record_are_code_written`, `test_writer_percentage_rejected`, `test_station_id_line_3_in_record_part`.
- [ ] **Step 2–4:** FAIL, implement, PASS. Commit.
