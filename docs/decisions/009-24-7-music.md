# 009 — Music around the clock: a program director, a shared schedule, one hourly trigger

**Decision** — The flagship music station (Rhythm Lab) is programmed 24 hours a day by a program director built from code and Jev: songs sit in rotation categories with rest times, every hour follows a day or overnight clock, a weekly music meeting decides what moves, and a queue of exact start times is kept 2 hours ahead and published. The hourly trigger now fires every hour; outside newscast hours it runs only the music station.

**Why this came up** — Tarik asked (Nov 27) how to run 24/7 streams, and then for the agent to "act like a program director" with real radio rotation practice. The PRD rules out a broadcast stream: songs play through each listener's own Apple Music, so nothing can be streamed from our servers. What a station can share is a schedule everyone's browser follows. Getting this wrong means either a station that repeats itself every hour or one that a model programs on a whim, which nobody could audit.

**Options**
1. **Program director as code plus Jev, a shared queue, every hour.** Categories, rests, clocks and separation are code; adds, moves and burn-out are Jev's yes/no answers, logged with probabilities. Cost: the most code of the three (scheduler, meeting, queue, pages), and a station needs a big enough catalog to fill a clock.
2. **Keep the hourly 50-minute sampler set, extended overnight.** Already built. Cost: no rotation memory beyond "not played in 3 hours", no hour shape, and nothing a radio person would recognise as programming.
3. **Let a language model pick each next song.** Least code. Cost: no rule anyone can check, and it breaks the station's founding rule that a language model never chooses what airs.

**What we chose and why** — Option 1. Tarik chose the program director approach ("Plan B a"); Claude chose the details (rest times, clocks, the 25% churn cap, fixed points at :00 and :30) from common music-radio practice. ONE Jazz stays on the sampler for now (option 2): its ~30 matched songs cannot fill a 24-hour clock with these rest times; Rhythm Lab's 2,513 can.

**What we gave up** — ONE Jazz is not 24/7 yet. Overnight runs read no feeds, so new finds wait until morning. A station's hour is planned an hour or two ahead, so a song added at a meeting is not heard until the queue reaches it. The Cloudflare Worker now wakes the Sprite 24 times a day instead of 13.

**How we'll know if this was right** — After a night unattended: the queue is never less than 2 hours ahead, no artist repeats within 3 hours in the published queue, :00 and :30 items start on the second, and the meeting page shows every change with Jev's probability and a reason.
